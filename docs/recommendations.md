# Как формируются рекомендации

## Отбор и ранжирование

1. Проверить драфт и исключить из списка кандидатов союзников, противников и забаненных героев.
2. Для каждого кандидата оценить соответствие роли и собрать результаты двух независимых агентов. Агент меты использует статистику по выбранному патчу, размер выборки и рейтинговый сегмент, если он задан. Агент синергий и контрпиков сопоставляет игровые механики и дополняет правила статистикой пар и матчапов, где она доступна.
3. Привести оценки к шкале от 0 до 1 и рассчитать итоговый балл.
4. Взять до трёх героев с наибольшим баллом и подобрать им предметы с учётом роли и вражеского состава. При равных баллах порядок определяется по ID героя для воспроизводимости.
5. Собрать для финалистов объяснения, риски и предметы. Если допустимых героев меньше трёх, вернуть всех доступных. Пустой список означает, что доступных кандидатов нет.

Стартовая формула для MVP складывает четыре взвешенные оценки.

```text
score = 0.25 × meta + 0.30 × synergy + 0.30 × counter + 0.15 × role_fit
```

Веса предварительные. `counter` показывает, насколько герой подходит против уже выбранных соперников. `role_fit` влияет на балл как отдельный фактор. Итоговый балл служит для ранжирования. Предметы добавляются к карточкам после ранжирования.

## Объяснения и ограничения

Агенты передают аргументы в `evidence`. Каждый аргумент должен опираться на статистику, свойство способности или явно заданное правило. Агент отмечает малую выборку и неполное покрытие в `risks`. `confidence` отражает уверенность агента в оценке.

Агрегатор использует эти факты, чтобы объяснить сильные и слабые стороны пика. Для MVP достаточно шаблонов. Если подключить LLM, ей передаются готовые факты для формулировки текста. Порядок героев и значения баллов берутся из результата скоринга.

## Черновые контракты

В примерах условные идентификаторы и оценки. Форматы подлежат уточнению при реализации API.

### Вход API — `DraftContext`

```json
{
  "patch": "example_patch",
  "allies": ["mars", "snapfire"],
  "enemies": ["phantom_lancer", "storm_spirit"],
  "bans": ["axe"],
  "target_role": "carry",
  "rank_bracket": null
}
```

### Результат агента — `AgentResult`

```json
{
  "agent": "synergy_counter",
  "hero": "example_hero",
  "scores": {
    "synergy": 0.82,
    "counter": 0.76
  },
  "evidence": [
    {
      "type": "mechanic",
      "text": "Урон по области помогает справляться с иллюзиями."
    }
  ],
  "risks": ["Мало матчей для оценки конкретного матчапа."],
  "confidence": 0.65,
  "data_version": "example_dataset_v1"
}
```

### Ответ API — `DraftRecommendations`

```json
{
  "recommendations": [
    {
      "hero": "example_hero",
      "rank": 1,
      "total_score": 0.8065,
      "score_breakdown": {
        "meta": 0.79,
        "synergy": 0.82,
        "counter": 0.76,
        "role_fit": 0.90
      },
      "reasons": ["Урон по области помогает справляться с иллюзиями."],
      "risks": ["Мало матчей для оценки конкретного матчапа."],
      "items": [
        {
          "id": "example_item",
          "reason": "Дополнительный урон по области против иллюзий.",
          "priority": 1
        }
      ]
    }
  ],
  "patch": "example_patch",
  "data_version": "example_dataset_v1"
}
```

Приоритет `1` означает первый предмет в списке. Как выбирается снимок данных, описано на странице [«Данные»](data.md).
