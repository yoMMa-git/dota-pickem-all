# Данные и игровые знания

Для MVP нужен воспроизводимый снимок статистики и справочников для одного патча. Все агенты в рамках одного запроса используют согласованные версии данных. API возвращает патч и версию снимка вместе с рекомендациями.

## Возможные источники

| Источник | Что проверить для проекта |
|---|---|
| OpenDota | Доступность статистики героев, матчапов и истории матчей |
| STRATZ | Возможность дополнить статистику матчей и получить данные для персонализации после MVP |
| dotaconstants | Покрытие справочников героев, способностей и предметов |
| Официальные патчноуты Dota 2 | Изменения баланса и механик, влияющие на правила анализа |

Перед выбором источников нужно проверить покрытие нужного патча, условия доступа и лимиты. Для демо и экспериментов используется заранее подготовленный снимок.

## Подготовка и использование снимка

1. Загрузить статистику и справочники отдельно от обработки запросов.
2. Привести ID героев, способностей и предметов к единым идентификаторам.
3. Сохранить для статистики патч, источник, дату обновления и размер выборки, где он доступен. При наличии сегментации сохранить роль и рейтинговый сегмент.
4. Подготовить версионированный справочник механик с тегами способностей и правилами взаимодействий. Например, тег урона по области пригодится для оценки пика против героев с иллюзиями.
5. Опубликовать версию снимка с указанием версии справочника. Бэкенд читает эти данные из локального хранилища во время анализа драфта.

Если запрошенный патч отсутствует, API сообщает, для каких патчей есть данные. При малой выборке или неполном покрытии механик агенты передают ограничения в ответ. Данные разных патчей хранятся раздельно.

## Планируемые сущности

| Группа | Сущности |
|---|---|
| Справочники | `heroes`, `abilities`, `ability_tags`, `items`, `patches` |
| Статистика | `hero_stats`, `hero_matchups`, `hero_synergies` |

Для повторения эксперимента нужно сохранить патч, версию снимка и правил, веса скоринга и набор сценариев. См. [план проверки](roadmap.md#проверка-качества).
